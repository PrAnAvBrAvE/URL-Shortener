# URL Shortener API

A RESTful URL Shortener API built with Node.js, Express.js, MongoDB, and Mongoose. It allows users to create short URLs, redirect to original URLs, and retrieve URL records with pagination.

## Features

- Create short URLs for valid HTTP and HTTPS URLs.
- Redirect short codes to their original URLs using HTTP 302.
- Validate request bodies and URL protocols.
- Centralized error handling with consistent JSON responses.
- MongoDB persistence using Mongoose.
- Automatic `createdAt` and `updatedAt` timestamps.
- Pagination with configurable page and limit parameters.
- MongoDB indexing for unique short codes.
- Structured HTTP request logging using Pino.
- Automated API integration tests using Jest and Supertest.

## Tech Stack

- **Runtime:** Node.js
- **Framework:** Express.js
- **Database:** MongoDB
- **ODM:** Mongoose
- **Logging:** Pino, pino-http
- **Testing:** Jest, Supertest
- **Configuration:** dotenv

## Prerequisites

- Node.js and npm
- A MongoDB instance or MongoDB Atlas cluster

## Getting Started

### 1. Clone the repository

```bash
git clone <your-repository-url>
cd url-shortener-api
```

### 2. Install dependencies

```bash
npm install
```

### 3. Configure environment variables

Create a `.env` file in the project root:

```dotenv
PORT=3000
MONGODB_URI=your_development_mongodb_connection_string
MONGODB_TEST_URI=your_test_mongodb_connection_string
LOG_LEVEL=info
```

Use a separate database for testing. Never commit your `.env` file or expose database credentials.

### 4. Start the development server

```bash
npm run dev
```

The server connects to MongoDB and starts listening on the configured port.

## API Endpoints

### Health Check

`GET /health`

Checks whether the API responds.

**Success response — `200 OK`**

```json
{
  "status": "ok"
}
```

### Create a Short URL

`POST /api/urls`

**Request body**

```json
{
  "originalUrl": "https://example.com/some-long-page"
}
```

**Success response — `201 Created`**

```json
{
  "originalUrl": "https://example.com/some-long-page",
  "shortCode": "generatedCode"
}
```

The short code is generated by the server and the URL record is saved in MongoDB.

### Redirect to the Original URL

`GET /:shortCode`

Example:

`GET /generatedCode`

- `302 Found` — redirects to the original URL.
- `404 Not Found` — the short code does not exist.

### List URLs with Pagination

`GET /api/urls?page=1&limit=10`

Both query parameters are optional and default to `page=1` and `limit=10`. The limit must be between 1 and 100.

**Success response — `200 OK`**

```json
{
  "success": true,
  "data": [],
  "pagination": {
    "page": 1,
    "limit": 10,
    "total": 0,
    "totalPages": 0
  }
}
```

The `data` array contains the URL records for the requested page.

## Error Handling

The API returns appropriate HTTP status codes for validation errors, missing short codes, malformed JSON, and unexpected server errors.

Example error response:

```json
{
  "success": false,
  "status": 400,
  "message": "Invalid URL"
}
```

Unexpected server errors return a generic message to the client, while detailed errors are logged on the server.

## Testing

Run the automated integration test suite:

```bash
npm test
```

The tests use Jest and Supertest to verify API responses, validation, redirects, and pagination against a separate MongoDB test database.
